# SOCF Thread Fix - Complete Instructions for Replit Agent

## Problem Statement

The SOCF (Socket connection of the field) thread in `farmer.py` is not receiving field objects from the server. Analysis of browser WebSocket traffic and current implementation reveals critical timing and protocol issues.

## Root Cause Analysis

### Browser Behavior (Correct):
```
1. Connect → Send JWT token
2. Send kingdom data
3. WAIT for /field/enter/v3 RESPONSE
4. After response → Send zone handshake sequence
5. WAIT for /field/objects/v4 RESPONSE
6. After response → Start scanning loop
```

### Current Code Behavior (Wrong):
```
1. Connect → Send JWT token
2. Send kingdom data
3. Send zone handshake immediately (NO WAIT)
4. Timeout after 30s - no field objects received
```

**The code sends all messages at once without waiting for server responses between steps.**

## Evidence from Logs

Current implementation logs show all messages sent at the same timestamp:
```
08:03:22.185 - SOCF SOCKET CONNECTED
08:03:22.185 - Sending /field/enter/v3 JWT
08:03:22.185 - Sending /field/enter/v3 Object
08:03:22.185 - Zone Step 1: /zone/leave/list/v2    ← ALL AT SAME TIME
08:03:22.185 - Zone Step 2: /zone/enter/list/v4    ← NO WAIT
08:03:22.185 - Zone Step 3: /zone/leave/list/v2    ← NO WAIT
08:03:22.185 - Zone Step 4: /zone/enter/list/v4    ← NO WAIT
...
08:03:52.596 - Timeout (30s) - no /field/objects/v4 received ← FAILURE
```

Browser logs show proper timing with responses between steps:
```
17:53:23.732 - Connect
17:53:24.039 - Send JWT + kingdom data
17:53:24.373 - WAIT then send zone leave        ← DELAYED
17:53:24.433 - Send zone enter                  ← DELAYED
17:53:24.440 - Receive /field/objects/v4        ← SUCCESS
```

## Required Changes

### File to Modify
- `farmer.py` - Method: `_socf_thread_internal(self, radius, targets, share_to=None)`

### Critical Fixes Needed

#### Fix 1: Move Zone Handshake Out of `on_connect()`

**Current Code Location** (around line 4069):
```python
@sio.on('connect')
def on_connect():
    # ... send JWT and kingdom data ...
    
    # WRONG: Zone messages sent here immediately
    sio.emit('/zone/leave/list/v2', ...)
    sio.emit('/zone/enter/list/v4', ...)
    sio.emit('/zone/leave/list/v2', ...)
    sio.emit('/zone/enter/list/v4', ...)
```

**Must Change To**:
```python
@sio.on('connect')
def on_connect():
    # ... send JWT and kingdom data ...
    
    # REMOVE all zone emit calls from here
    # Zone messages will be sent in the /field/enter/v3 handler instead
```

#### Fix 2: Add Threading Event for Synchronization

**Add at method start** (around line 3990):
```python
# Threading events for proper sequencing
field_enter_response_received = threading.Event()
field_objects_received = threading.Event()
```

#### Fix 3: Create/Modify `/field/enter/v3` Response Handler

**Current Code Location** (around line 4091):
```python
@sio.on('/field/enter/v3')
def on_field_enter(data):
    # ... parse data ...
    
    # ADD: Signal that response was received
    field_enter_response_received.set()
    
    # ADD: NOW send zone handshake sequence HERE
    time.sleep(0.05)
    
    # Step 3a: Leave empty zones
    logger.info(f'[{current_time}] Step 3a: Leave empty zones')
    sio.emit('/zone/leave/list/v2', {
        'world': self.socf_world_id,
        'zones': '[]'
    })
    time.sleep(0.05)
    
    # Step 3b: Enter initial zones [0,96,1,97] - BASE64
    initial_zones = [0, 96, 1, 97]
    zones_payload = {
        "world": self.socf_world_id,
        "zones": json.dumps(initial_zones)
    }
    zones_base64 = base64.b64encode(json.dumps(zones_payload).encode()).decode()
    
    logger.info(f'[{current_time}] Step 3b: Enter initial zones {initial_zones} (BASE64)')
    sio.emit('/zone/enter/list/v4', zones_base64)
    time.sleep(0.05)
    
    # Step 3c: Leave initial zones
    logger.info(f'[{current_time}] Step 3c: Leave initial zones')
    sio.emit('/zone/leave/list/v2', {
        'world': self.socf_world_id,
        'zones': json.dumps(initial_zones)
    })
    time.sleep(0.05)
    
    # Step 3d: Enter target zones - BASE64
    if self.zones:
        target_zones = self.zones[:9]
        zones_payload = {
            "world": self.socf_world_id,
            "zones": json.dumps(target_zones)
        }
        zones_base64 = base64.b64encode(json.dumps(zones_payload).encode()).decode()
        
        logger.info(f'[{current_time}] Step 3d: Enter target zones (count: {len(target_zones)}) (BASE64)')
        sio.emit('/zone/enter/list/v4', zones_base64)
```

- The `base64` import must be at the top of the file

- The zone leave messages MUST be plain JSON (NOT base64)
- Threading events ensure proper synchronization
- All zone messages moved from `on_connect()` to `on_field_enter()`

## Summary

**Core Issue**: Zone handshake sent too early without waiting for server response  
**Solution**: Use threading events to wait for `/field/enter/v3` response before sending zone messages  
**Impact**: Enables proper server communication and field object reception
